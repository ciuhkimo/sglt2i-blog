# TFDA 監管週報 — 抓取資料存檔

本目錄存放 `scripts/fetch-tfda-updates.mjs` 每週自動抓取的**原始結果**，
由 `.github/workflows/tfda-weekly.yml` 於每週一 commit 進來。

## 為什麼存在（2026-10-09 建立）

這條線原本是「每週抓取 → 寫內容草稿 → 開 draft PR 等醫師審閱」。
問題不是 PR 數量，是**資料會腐壞**：

- 來源 RSS 只保留近期項目，視窗會滾過。草稿積壓一個月後，**事後無法一手核對**。
  2026-09-12 已實證：重跑驗證時衛福部焦點新聞最舊只到 09-01，
  反而漏掉該期最重要的健保給付那一則。
- 被排除（非目標範圍）的項目連紀錄都不留：`work/tfda/` 同時被 `.gitignore`
  與 PR 的 `add-paths` 兩道獨立阻擋，CI 跑完即消失。
- 草稿的「未收錄」清單還被 `excluded.slice(0, 20)` 截斷（已於 2026-10-09 移除）。

所以把**抓取**與**發佈**解耦：抓取每週自動存檔（便宜、不需要人），
發佈改為需要時的人工流程（貴、需要一手核對）。

## 目錄內容

每週一個目錄，以**週結束日**命名：

| 檔案 | 內容 |
|---|---|
| `items.json` | 該週所有抓到的項目（含分類、重要度、`include_in_public_weekly` 旗標） |
| `digest.md` | 人可讀的摘要 |
| `weekly-draft.md` | 腳本初整的週報草稿（**未經醫師審閱，不得直接發佈**） |

## ⚠️ 2026-09-13 ~ 2026-10-04 四週的來源與限制

這四週原本是積壓中的 draft PR #13–#16（2026-10-09 關閉）。每週目錄下有兩種來源：

| 檔案 | 來源 | 完整性 |
|---|---|---|
| `weekly-draft.md` | 從已關閉的 PR 分支搶救 | in-scope 項目**完整**（含官方原文連結）；無完整項目清單、無被排除項目紀錄 |
| `items-refetched-2026-10-09.*` | 2026-10-09 以當時 feed 設定重抓 | 有完整 `items.json` 與未截斷的排除清單，但**來源 RSS 視窗已部分滾過**，項目數較當時少 |

實測對照（2026-10-09）：

| 週 | 當時草稿 in-scope | 重抓 in-scope | 重抓總則數 |
|---|---|---|---|
| 09-07 ~ 09-13 | 5 | 4 | 12 |
| 09-14 ~ 09-20 | 8 | 6 | 18 |
| 09-21 ~ 09-27 | 2 | 4 | 19 |
| 09-28 ~ 10-04 | 11 | 7 | 30 |

兩份是**互補**的，不是其中一份取代另一份：

- 舊草稿反映當時 feed 設定（早期僅 4 個 RSS）
- 重抓反映現行設定（11 個 RSS），所以 09-21~09-27 重抓到的 in-scope 反而比當時多

### 仍然可以做什麼、不能做什麼

- ✅ **這四週仍可出刊**。草稿裡 26 條 in-scope 項目全部帶官方原文連結，
  連結不會因 RSS 視窗滾過而失效，一手核對照樣做得到。
- ❌ **當時被判「排除」的項目清單已永久遺失**（`work/tfda/` 同時被 `.gitignore`
  與 PR `add-paths` 兩道阻擋，CI 跑完即消失），且舊草稿的排除清單還被
  `excluded.slice(0, 20)` 截斷。重抓無法還原當時的排除判定。
- ⚠️ 因此這四週**不能宣稱「本期已完整掃描」**，只能說「以下為當時收錄候選」。

## 這些檔案不是已驗證內容

`weekly-draft.md` 是自動化初整產物。依 vault 紀律：

- 分類與重要度僅供初判
- 「可能影響」欄位是 placeholder，未經醫師審閱
- 自動化產出的標籤、框架、法規狀態**一律當未驗處理**
- 要出刊必須逐則回官方原文一手核對

本目錄**不在 Astro content collection 內，不會被建成任何頁面**。

## 要出刊時怎麼做

```bash
# 1. 在本機重跑指定區間並產生內容草稿
node scripts/fetch-tfda-updates.mjs --from <起日> --to <迄日> --promote

# 2. 逐則回官方原文一手核對、改寫草稿
# 3. 走既有發佈 routine
npm run build:verify
npm run tfda:publish -- <slug>
```
